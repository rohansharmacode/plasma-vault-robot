Team PLASMA: a talking robot that reboots the vault

Code for our UBTECH UGOT Engineer robot at the Robomasters hackathon "Reboot the Vault". After one start command the robot runs the missions on its own and says what it is doing at every step. The voice is made with ElevenLabs.

View the code on GitHub github.com/rohansharmacode/plasma-vault-robot
Robot
UBTECH UGOT Engineer (mecanum wheels, 3-joint arm, clamp, camera, IR distance sensor)
Code
Python 3.12, MIT licence
Voice
ElevenLabs text-to-speech, plasma_ai.py

Every spoken line takes one ElevenLabs route, with two fallbacks so the robot is never silent

Robot line

All speech goes through one function, Robot.say(). It also prints the line on the robot's screen and in the dashboard log.

ElevenLabs

A POST to /v1/text-to-speech/{voice_id} with model eleven_multilingual_v2. The API key comes from ELEVENLABS_API_KEY, never from the code.

WAV cache

The reply is raw 22,050 Hz PCM, wrapped as a mono WAV. The file name is a hash of voice and text, so each line is paid for once.

Upload

The WAV goes to the robot over HTTP (port 7000). A test clip finds which of 10 known upload addresses works, and the address is remembered.

Robot speaker

The robot plays the uploaded file. The code waits for the clip length, so lines never cut each other off and the microphone does not hear the robot.

65 lines are made before the run

At start-up, Voice.prepare() makes and uploads every fixed line, so there is no network wait during a mission. After the first run they come from the cache.

  • "Team Plasma." Every run starts with the team name (team rule)
  • "Plasma online. Let's light it up." One of three start-up catchphrases
  • "Tape locked. Let's ride." Mission 2, tape following
  • "Decrypting evidence. Stand by." Mission 4, QR evidence
  • "Core in transit. Nobody breathe." Missions 5 and 6, carrying the core

Some lines are made live

Lines that depend on what the robot finds are generated during the run, with an 8-second limit so the voice never holds up a mission.

  • "QR message 1 says: ..." The decoded QR evidence, read aloud in full
  • "Battery at 82 percent. Pitch 1 degree ..." Mission 3 status report after the robot turns to a clap (example values)
  • Gemma 4 reveal Mission 6: Gemma 4 writes two sentences on how the evidence identified the core, ElevenLabs speaks them
  • Typed lines --mission say: type a line and the robot says it in the ElevenLabs voice

Built so the voice cannot stop a mission

  • Two fallbacks. If the robot upload fails, the ElevenLabs clip plays on the laptop speaker. If ElevenLabs fails, the robot's built-in voice says the line.
  • Circuit breaker. If ElevenLabs cannot be reached once, the run goes offline: cached lines still play, and new lines use the robot voice without waiting again.
  • Never blocks driving. Lines said during tape following run in a background thread, so the control loop keeps steering.
  • Practice mode. --mock writes silent clips to a separate cache, so test data never mixes with real voice files.
  • Privacy. QR text is checked before it is spoken. A Wi-Fi password in a QR, plain or encoded, is masked and the robot says "a Wi-Fi network code".
  • Check on the robot. --mission voicetest finds the upload address and plays every catchphrase.

At the event, the robot spoke with ElevenLabs. It said its commands and what it was doing in a natural human voice, not the built-in robot voice. Known limits

  • The stop 15 to 25 cm before the blue wall does not work yet.
  • A very dense printed QR at about 70 cm is not read by the 640x480 camera.
  • Fully autonomous pickup (Missions 5 and 6) is not yet tested end to end.
  • Gemma 4 is not tested on the robot. The rule-based decoder gets 22 of 29 benchmark cases right.
